# Odin storage

By default Odin writes Markdown files to `.odin/vault` in the process working directory. `ODIN_VAULT_DIR` can point to another local directory. Local writes create a temporary file and rename it into place, and in-process mutations are serialized. Keep this directory on persistent storage and back it up. Odin refuses local writes on Vercel, where the filesystem is ephemeral.

Set `ODIN_STORAGE=drive` with `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN`, and `GOOGLE_DRIVE_FOLDER_ID` to use an existing Google Drive folder. The refresh token must have a Drive scope that permits reading and writing files in that folder. Values are read only on the server; the status endpoint returns no credentials. The adapter uses Google Drive REST APIs directly.

On Vercel, Drive writes require `ODIN_LOCK_REDIS_URL` and `ODIN_LOCK_REDIS_TOKEN` for an Upstash Redis REST endpoint. Odin stores only a short-lived lease token in Redis; the canonical entry data remains in Drive. Without a working Redis connection, `/api/status` reports `writable: false` and writes fail closed. A local single-process Drive installation may run without Redis. If Redis is configured locally, writes also require its lease. The lease expires after 30 seconds and is renewed every 10 seconds; remote requests have bounded timeouts. All writers to a folder must use the same Redis instance and lock key. Back up Drive data independently.

Each current entry and revision is a separate Markdown file with YAML front matter. `GET /api/export` downloads a ZIP with `entries/`, `history/`, optional `recovery/`, and a schema manifest. `GET /api/export?id=UUID` downloads one Markdown file. The ZIP preserves deleted entries, committed revisions, and any interrupted write candidates separately in `recovery/`. It can be unpacked into a vault by copying the `entries/` and `history/` Markdown files to the vault root; inspect `recovery/` before restoring those files. The manifest states the format version.

Creation retries can use the `Idempotency-Key` HTTP header. Odin writes a request identity record before creating the entry, and the key determines a stable UUID. Replaying after an interrupted save therefore reuses the same entry. Updates can clear `dueAt`, `projectId`, `relatedIds`, and `source` by sending explicit JSON `null`. Updates, deletion, and restoration require `expectedRevision`; a stale value returns HTTP 409. The local process serializes these checks.

Google Drive has no atomic compare-and-swap across separate requests or app instances. The optional Redis lease serializes compliant Odin writers across instances, and each operation refreshes its Drive filename index before reading. Do not write to the same folder with tools that bypass the lease. If a lease expires during a remote write, Odin reports failure, but the remote operation might already have committed; inspect the current entry and history before retrying. Revision filenames carry a unique suffix, and commit markers distinguish completed revisions from interrupted candidates.
